# 2人用の統一入力ラボ

同じActionReaderを持つ2体のCharacterへ、キーボード・ゲームパッド・Canvasタッチ・プログラムから入力します。切り替えてもActor・位置・Componentを作り直しません。v0.1.4候補ソース用のサンプルで、キーボード・タッチ・プログラムの確認に実機パッドは不要です。

```sh
npm ci
npm run dev -- --example unified-input
```

ゲーム領域を選択します。P1はWASDとF、P2はKeyboard + padモードで矢印とSlash、P1のPでpause/resumeできます。画面の各方向とFireはプレイヤーごとに独立したタッチ操作です。標準パッドは左スティック／十字キーでMove、SouthでFire、StartでPauseを操作します。

| 操作           | 内容                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| P1/P2のモード  | Keyboard + pad → Pad only → Program。ActorとReaderを維持                      |
| P1/P2 pad      | クリックしたときだけ、ブラウザが公開するindexを順に割り当て。初期はP1=0、P2=1 |
| Labels         | IDからの推定／汎用／Xbox／PlayStation／Nintendo表示を明示的に選択             |
| Pause / Resume | ゲーム状態を保って入力を解放。全割り当て入力を一度離してから新しい入力を開始  |
| New Scene      | 旧Controller・Source・購読を破棄してサンプルを生成し直す                      |
| Notes          | Canvasのネイティブ編集欄。編集中は物理キーボードとパッドのゲーム入力を抑止    |

方向ジェスチャーはそれぞれSourceを持ち、斜めの同時押しやキーボード／パッドとの合成ができます。Programモードはそのプレイヤーの他のSourceを無効化します。プログラムの方針はサンプル側の処理で、エンジンのAI機能ではありません。同じパッドを両プレイヤーへ明示的に割り当てることもできます。接続だけでプレイヤーを自動選択したり、切断時に自動代行へ切り替えたりはしません。

上部に元のID、mapping、ボタン・軸数、レイアウト推定を表示します。表示推定とブラウザ情報を混同しません。未マッピング機器は標準設定で入力しません。ブラウザが初回のパッド操作を待つ場合や、権限・HTTPS条件で情報を公開しない場合もあります。ID/indexを永続的な個体IDには使いません。

[ゲームパッドの契約](gamepads.md)にデッドゾーン、トリガー、再接続、明示的raw設定、表示名上書き、複数Controllerの規則をまとめています。[英語のサンプル説明](../../examples/unified-input/README.md)も参照できます。

自動テストは模擬Gamepad APIと実DOMフォーカス、エミュレートしたタッチで、両描画方式の切り替え・切断・pause・破棄を確認します。実機パッドやメーカー別の印字、OSドライバーの操作性は未検証です。
