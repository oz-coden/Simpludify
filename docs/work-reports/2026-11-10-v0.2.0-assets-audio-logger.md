## Architecture findings

Core runs synchronous simulation and uses `LifetimeOwner` for removable cleanup. Web owns asynchronous Scene setup, AbortSignals, input routing and presentation transactions. `Engine.activate` currently commits the incoming Scene, deactivates and disposes the outgoing Scene, then invokes activation hooks. `SceneState.Inactive` currently blocks acquisition. Retention needs an explicit transition policy while preserving Game's queue, readiness and input clearing.

The default Pixi renderer already coalesces decoded images and leases by resolved URL. It owns source textures and frame textures, aborts abandoned requests and releases textures at the last reference. Explicit image loads should share that store with existing URL consumers. The resource cache should keep bounded idle entries separately from live owners and visuals. Core render metadata remains independent of Pixi and browser objects.

Audio and fonts need browser decoding or registration and can use the same explicit loading and owner contracts as images. Audio playback has its own lifetime, independent of the decoded buffer. Canvas, DOM and renderer presentation state remain distinct from retained Scene simulation state.

## Phase 1 — Logger and diagnostics

Core provides `Logger`, structured `Diagnostic` records and optional `EngineError` cause, source and fatal metadata. Web exposes the Game instance through `game.logger` and installs a safe Console sink. `logging.console`, `minimumLevel` and `deduplicate` affect the sink. Subscribers receive all top-level entries in registration order, including repeated entries. Diagnostic callbacks may fail without propagating exceptions to the emitter. Recursive calls made synchronously by a diagnostic sink or subscriber are dropped at the dispatch boundary.

Diagnostics carry the original cause and details for subscribers. The standard sink and Game's alert use safe engine summaries. Logger emission does not determine Game state. Startup and committed presentation failures dispose the Game, staging failures preserve the prior active Scene, and frame or resize errors retain terminal handling. The old `GameOptions.onError` is a deprecated adapter for its established runtime callbacks and suppresses the default Console sink unless explicitly enabled.

## Phase 2 — Asset loading and image integration

`game.assets`, setup `assets` and `assets.scope(owner?)` share a Game-local directory. A scope owns one handle per typed URL, and a visible managed image retains an independent use. The underlying SharedImages pool still owns the Pixi source and its cropped textures. Legacy URL visuals preserve their existing readiness, failure and release behavior. The managed image reference selects a generation without changing the Core's image data format. Replacements validate live frame requirements before changing the Sprite texture.

The explicit loader supports images and JSON at this checkpoint. It distinguishes retryable network/HTTP failures from ordinary errors, keeps an available result during retries, and enforces a load deadline. A custom image fallback can fail safely to the generated checkerboard. The progress API publishes snapshots independently of diagnostics. Successful idle entries use a bounded least-recently-used cache. The cache limits idle entry count rather than decoded bytes.

## Phase 3 — Retained Scene lifecycle

Core retains an outgoing Scene only when explicitly requested. It tracks inactive owned Scenes until reactivation or disposal and clears physical input at the existing commit boundary. Web adds the Game default `sceneRetention` and the factory option `retention`. Retained factories run once per instance. Presentations, mounted DOM and temporary event hooks are released on departure and reconstructed on return. Asset scopes and asynchronous setup signals belong to the Scene rather than the presentation. A pre-commit reactivation failure leaves the active presentation intact and preserves the retained candidate for retry.

## Phase 4 — Audio and Font assets

Audio buffers and fonts use the existing typed Asset directory, retries, fallback and reference handling. The Web Game owns one lazy AudioContext. Each playback holds an independent buffer reference, can pause and resume from its prior position, and reports a terminal reason. Group volumes multiply along the hierarchy. Optional caps replace the oldest matching live voice. Trusted pointer and keyboard input attempt to resume pending audio. Scene or other lifetime ownership stops playback on disposal. Game-owned playback survives Scene changes. A failed audio decode can resolve to a custom asset or a silent one-frame buffer. Started voices keep the buffer they started with when an Asset reloads.

Fonts register under unique browser families and remove the FontFace when the last reference and any idle cache entry are released. `game.setFont()` holds a separate reference for Game DOM and Canvas UI. A node can explicitly choose its own font family. The first browser run found that changing the default updated DOM styling but could leave the cached Canvas style unchanged when layout bounds were identical. The resolved font now participates in both Canvas style signatures. The trusted gesture fixture now clicks the rendered canvas, where the actual game would receive pointer input.

The unit fixture verifies suspended playback, unlock, group gain composition, pause offset, owner cleanup and context closure. The Chromium cases exercise decoded audio sharing, queued activation, overlap limits, Scene- and Game-owned voices, silent fallback, real FontFace registration, Canvas updates and final unregister. ### Lifecycle and resource corrections

- Asset progress delivery now serializes reentrant changes through the store. Progress and handle observers isolate rejected asynchronous callbacks as well as synchronous exceptions. A successful generation clears the previous error before notifying consumers, and rejected replacements release the candidate before reporting failure.
- Managed Tilemap replacement checks frames from the current tile model at commit time. This covers tile edits made during an in-flight replacement, including changes made between renderer frames.
- Pending voices select the current AudioBuffer when playback begins. Started and paused voices keep their original generation and resume offset through reloads.
- If an activation hook disposes the incoming Scene after the Core commit, Web fails the transition, reports a fatal presentation diagnostic and disposes the Game and retained Scenes.
- The workspace, package manifests, lockfile, engine constant and package READMEs now identify the unpublished 0.2.0 candidate. Web depends on the exact matching Core version.

### Public API and scope

- Core exports `Logger`, structured diagnostic types, `EngineErrorOptions`, `SceneRetention` and the outgoing policy in `Engine.activate(next, { previous })`. Web re-exports the Core API.
- Web exposes `Game.logger`, `GameOptions.logging`, `Game.assets`, `SceneContext.assets`, scoped handles and progress, `Game.audio` groups/playback, `Game.setFont`, `GameOptions.sceneRetention` and per-registration retention.
- The default renderer shares initial URL image resources. Managed sources opt into generation replacement. The idle cache is bounded by entry count. Audio is buffered in memory, subject to browser autoplay policy, and has no streaming mode. A Scene-owned voice can stay active while its Scene is retained. Chromium is the automated browser target.
- Existing default Scene disposal, `changeScene` request ordering, Core's DOM-free boundary and existing input bindings remain covered. Engine Console summaries omit structured causes and details; diagnostic subscribers can access them.
