## Architecture findings

Core runs synchronous simulation and uses `LifetimeOwner` for removable cleanup. Web owns asynchronous Scene setup, AbortSignals, input routing and presentation transactions. `Engine.activate` currently commits the incoming Scene, deactivates and disposes the outgoing Scene, then invokes activation hooks. `SceneState.Inactive` currently blocks acquisition. Retention needs an explicit transition policy while preserving Game's queue, readiness and input clearing.

The default Pixi renderer already coalesces decoded images and leases by resolved URL. It owns source textures and frame textures, aborts abandoned requests and releases textures at the last reference. Explicit image loads should share that store with existing URL consumers. The resource cache should keep bounded idle entries separately from live owners and visuals. Core render metadata remains independent of Pixi and browser objects.

Audio and fonts need browser decoding or registration and can use the same explicit loading and owner contracts as images. Audio playback has its own lifetime, independent of the decoded buffer. Canvas, DOM and renderer presentation state remain distinct from retained Scene simulation state.

## Phase 1 — Logger and diagnostics

Core provides `Logger`, structured `Diagnostic` records and optional `EngineError` cause, source and fatal metadata. Web exposes the Game instance through `game.logger` and installs a safe Console sink. `logging.console`, `minimumLevel` and `deduplicate` affect the sink. Subscribers receive all top-level entries in registration order, including repeated entries. Diagnostic callbacks may fail without propagating exceptions to the emitter. Recursive calls made synchronously by a diagnostic sink or subscriber are dropped at the dispatch boundary.

Diagnostics carry the original cause and details for subscribers. The standard sink and Game's alert use safe engine summaries. Logger emission does not determine Game state. Startup and committed presentation failures dispose the Game, staging failures preserve the prior active Scene, and frame or resize errors retain terminal handling. The old `GameOptions.onError` is a deprecated adapter for its established runtime callbacks and suppresses the default Console sink unless explicitly enabled.

Coverage includes duplicate order and distinct details/causes, output filtering, muted subscribers, owner disposal, callback isolation, recoverable Scene setup failure, and fatal frame failure with Console disabled. Full branch CI is tracked separately from local checks.
Local `npm run check` passed TypeScript, architecture, license and Biome checks with the baseline 11 warnings and 12 informational diagnostics. `npm test` passed 895 tests and `npm run build -- --target web` passed. Browser validation and branch CI follow this checkpoint.
