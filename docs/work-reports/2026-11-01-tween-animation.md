## Adopted design

- Numeric-only, immutable Tween recipes: explicit number bindings, sequence/parallel/delay, leaf repeat/yoyo. A Scheduler owns live Playback handles. Plain numeric object properties are an opt-in convenience restricted to writable own data properties on plain objects; Actor/UI classes require explicit adapters. No arbitrary private-field traversal, vector/color coercion, global RAF or Pixi/DOM reference in Core.
- Seconds are explicit. Scene simulation scheduler captures eligibility before input and advances after contacts/before timers; new work during a captured step starts next step. A separate Scene presentation scheduler advances once per visible Web frame with the existing host delta cap, including during Engine pause. Fixed/replay simulation steps remain authoritative; display animation is not replay state. Each Scheduler also supports explicit headless advance and validated speed.
- Playback pause/resume retains claims; cancel/stop leaves the current value and never completes; finite finish applies terminal values and completes once. Zero duration is deferred to the next update/finish. Callbacks are synchronous, terminal cleanup precedes notification, errors aggregate, recursive advancement is rejected, and additions wait for the next clock boundary. Negative/nonfinite settings reject. Numeric repeat/yoyo uses bounded arithmetic rather than one callback/loop per skipped cycle. Composite-loop/timeline-editor features are deferred rather than exposed incompletely.
- Claims are canonical target/key identities across clocks/schedulers. New playback replaces overlapping owners by default; error mode rejects atomically. A composite reserves all its channels; overlapping parallel tracks on the same channel reject. Sequence reuse is allowed. Newer intent created reentrantly during cancellation wins. Owner disposal, external changes and adapter invalidation cancel entire playback and remove claims/subscriptions. Explicit custom bindings are responsible for their setter semantics.
- Actor adapters animate Renderable-only offset/rotation/scale/opacity; Transform, Motion, Collider and Body remain authoritative for world positions. SpriteAnimation keeps exclusive source/frame responsibility. This baseline deliberately does not offer unsafe physical-position tweening.
- Canvas presentation offset/opacity is separate from Flex style. Offset projection reuses scroll projection and updates descendants, native editor geometry, clips and hit tests together without repeated Flex measurement. Opacity is inherited; fully transparent UI is unavailable for pointer/focus. UI rotation/scale/color interpolation is deferred; no partial transform API will be exposed.
- Slider logical animation uses program-value notifications and never user commit; explicit command/edit intent cancels immediately, including same-value pointer start/program writes, reentrant observers, range and availability changes. A distinct display value can animate the bar while logical value stays immediate; pointer/key/program/range updates restore authoritative display. Both share the same cancellation/ownership machinery and numeric normalization.

## Tween Core checkpoint

Implemented explicit numeric capabilities, plain-record property validation, seven normalized easing functions, immutable to/delay/sequence/parallel recipes, bounded numeric repeat/yoyo, Playback pause/resume/cancel/stop/finite finish and an explicit Scheduler clock. Claims are shared across schedulers, replacement reserves the new owner before old cancellation observers, and parallel aliasing rejects before mutation. Scheduler rosters rebuild on membership changes rather than allocating on every frame; terminal handles release targets, claims, owner/watch subscriptions and scheduler references. Recursive advance/finish and asynchronous hooks/callbacks are diagnosed; failures release state and aggregate after other eligible work. No Host import or dependency was introduced.

Focused Core regression suite: **29 passed, 0 failed**. Covers normalized easings, delay/zero/large times, repeat/yoyo, clock speed, finite finish, composition leftovers, cross-clock conflicts, reentrant replacement, external writes including a later parallel channel, owner destruction, callback failure/reentrancy, paused callbacks, invalid settings and deterministic explicit steps. TypeScript passed after correcting a private optional-channel annotation and removing an unused test import. Scene clocks/adapters/sample and full integration gates remain pending.

## Scene clocks and ownership checkpoint

Added lazy Scene `tweens` and `presentationTweens` plus explicit `advancePresentation(seconds)`, with current-Scene Game getters and staged SceneContext accessors. Simulation eligibility is captured before input and updates after contacts/before timers; paused simulation does not advance. Web supplies capped visible frame delta to the display clock, independent of fixed/replay simulation and paused UI scrolling. Scene teardown disposes both schedulers before Actor cleanup. Scope checks prevent Actor/UI adapters from crossing Scene clocks. Existing clocks are not advanced by layout/resize.
