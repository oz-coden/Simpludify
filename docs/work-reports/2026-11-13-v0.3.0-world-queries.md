# Simpludify v0.3.0 world queries, masks and input activity

## Baseline and design

The starting main revision was `74a3f11c1d91ac20d5808f7e4c1795c681259392`. Both public SDK packages were at 0.2.1 and the [baseline CI](https://github.com/oz-coden/Simpludify/actions/runs/42845513248) succeeded. Work is tracked on [feat/v0.3.0-world-queries](https://github.com/oz-coden/Simpludify/tree/feat/v0.3.0-world-queries).

- CollisionWorld exposes queries over the Scene's existing Actor roster and Tilemap ownership. Each query reads current transforms and tile policies and reuses the contact geometry representation with separate scratch data. Queries do not update the contact solver's registration order. Traversing the segment's tile strips avoids scanning its entire bounding rectangle. Raycasting does not emit contacts or run the solver.
- PixiRenderer already separates world visuals, the viewport clip and screen UI. A Scene-level Graphics mask shares the world projection, clips the union of rectangles, circles and simple polygons and uses WebGL stencil or Canvas2D paths. Retained Scenes keep mask data while their presentation is rebuilt. Neither backend needs an offscreen texture for this clip.
- Game records physical activity through the existing scoped keyboard, routed pointer and assigned gamepad adapters. The read-only result does not participate in Action composition, Scene simulation or replay.

## Checkpoint

The initial static checks, five raycast tests, four mask browser cases and two input activity cases passed locally. Release preparation still requires the final cross-checks, bilingual reference and consumer verification. See the CI workflow for the full browser and package matrix.

## Release candidate validation

The SDK versions, package READMEs, Engine constant and exact Web-to-Core dependency are synchronized at 0.3.0. The npm lockfile contains no external dependency upgrades. Bilingual API examples cover all three features, and the independent packed Web consumer exercises them at runtime.

A local Straidhold checkout at `1966d77492d50c9b1930c715b5071744abacc7be` installed the candidate tarballs. It passed type checking, production build and 13 unit tests, including a comparison against its original wall query for 10,398 closed line segments. The comparison found an exact corner that was initially lost to floating-point rounding. The corrected cast matched obstruction and first-hit distance throughout the sample, and the SDK now has a regression test for that corner. Straidhold's padded route query has different semantics from an infinitesimally thin ray.

A 256 × 256 diagonal grid test visits fewer than 800 collision cells and returns 766 intersections. A nearest query on the same populated grid needs fewer than five cell probes. On a reverse horizontal ray across that grid, the nearest query only probes the first cell. The cell counts measure algorithmic work independently of hardware.

Local checks passed with 916 unit tests, six focused Chromium cases, the packed SDK consumer and 109 typechecked documentation examples. An earlier run overlapped browser and packaging work and hit an existing accelerated simulation test timeout. The isolated unit suite passed.
