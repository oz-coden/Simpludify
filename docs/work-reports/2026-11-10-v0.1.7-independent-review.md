## Independent findings and fixes

| Area                                    | Review result and coverage                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scene queue                             | A single tail marker correctly coalesces adjacent identical requests while retaining each intervening target. Clearing the marker at activation permits a synchronous hook to enqueue a new navigation with an independent Promise. The regressions verify active A to B to A, B to C to B, setup failure during a mixed queue, settlement and cleanup order, fresh Scene instances, aborted signals and final input ownership. The existing pending-disposal and committed-lifecycle-error cases remain.                                                              |
| Scene failures                          | A factory that disposes its Game before returning a rejected Promise could leave that Promise unobserved. The Game now observes it. The existing terminal cleanup on first-render failure is retained. An earlier error in pointer routing or DOM installation could skip cleanup of the replaced presentation. The transaction now transfers ownership before host installation and cleans the replaced presentation in a finally block. Tests verify the original rejection, queued `GAME_DISPOSED` results and cleanup of both presentations.                       |
| Tilemap reconciliation                  | Separate visual maps correctly track the two layer types, but the existing count assertion passed even when the sprite sheet lease was discarded. The lease check used the map's internal placement instead of the Actor carrying its layer. Reconciliation now checks that Actor, skips disposed maps, and applies Actor and layer enable flags to both visual types. Pixel tests cover equal and changed depth, disable and enable, same-map reuse, two replacements in one frame, both map types, removal and re-addition, and lease release in WebGL and Canvas2D. |
| Gamepad bindings                        | The last entry for a physical button wins within one Action, including a threshold change via `addBindings`. Different Actions or binding paths still report a conflict. Tests cover physical-index removal, cross-Action conflict, and validation of every input before deduplication so an invalid threshold cannot be hidden by a later entry. An explicit null threshold now fails validation.                                                                                                                                                                     |
| Canvas input                            | The native wheel zero-rect guard is correct, but the corresponding test described in the initial report was absent from the diff. Host-level wheel and captured pointer events could still attempt projection on a collapsed rectangle. Both wheel routes now ignore the collapsed host and pointer release clears the held state. The new browser test checks real DOM dispatch, zero capture after release, no wheel consumption and no error in both renderers.                                                                                                     |
| Scene registration and tile coordinates | Invalid Scene names and factory values fail at registration, as tested by the original review. The signed-zero Tilemap normalization preserves out-of-bounds behavior for finite inputs. The original unit regression checks both axes with `Object.is`.                                                                                                                                                                                                                                                                                                               |
| Released starter and registry           | The renamed method is exposed by candidate Web only. The distributed starter retains the restart call matching its published v0.1.6 lock. Candidate or newer registry validation updates the isolated starter copy to `changeScene`. The package fixture likewise selects the published call only for the isolated v0.1.6 registry check. There is no compatibility alias in the SDK.                                                                                                                                                                                  |

Activation hooks run synchronously. After startup they can enqueue navigation and handle its Promise separately. Navigation requested from inside an asynchronous factory starts after that factory's own transaction settles.

## Verification

Local checks passed for `npm run check`, `npm test` (892 tests), `npm run test:build`, `npm run pack:packages`, `npm run test:packages -- --packed`, `npm run test:starter -- --packed`, `npm run site:build -- --base /Simpludify/`, `npm run site:check` and `npm run test:site`. The same candidate archives passed Run To Exit's isolated installation, TypeScript check, 35 unit tests and production build with `npm run test:consumer:prepare`. The separate `npm run test:packages:registry` and `npm run test:starter:registry` checks passed against published Core and Web v0.1.6.

The [first recovery run](https://github.com/oz-coden/Simpludify/actions/runs/42658089191) passed all 18 applicable jobs at `ebf086401660694215c783cd3e792f26a9c7cc99`. Its six source browser shards ran 462 tests. The consumer build ran 35 unit tests, and the four consumer jobs ran 66 E2E tests across the six renderer and viewport combinations. The deployment and published-site jobs were skipped by the branch gate.

The [next branch run](https://github.com/oz-coden/Simpludify/actions/runs/42709118801/job/129474003733) passed 17 applicable jobs and timed out in Run To Exit's desktop WebGL layout case. The [trace](https://github.com/oz-coden/Simpludify/actions/runs/42709118801/artifacts/13715027477) recorded a map width of 140.83 px at the 390 px breakpoint and showed that the editor was still visible. The test advanced the paused animation clock immediately after resizing. If the browser delivered its resize notification afterward, the app received the new dimensions with no subsequent update to switch to compact layout. A controlled local reproduction deferred the Game's resize callback until after the clock advance and left the editor visible with a 127.53 px map. Advancing the clock again applied compact layout with a 346 px map. The fixture now waits for the host's resize delivery before advancing the clock. It retains the map width and overflow checks and verifies the editor visibility for each width. The revised case passed three times in each of the six configurations, and all 66 consumer E2E tests passed against the candidate build locally with Playwright retries disabled.

The desktop regression tests were also run against the original review commit. The queue and first-render termination expectations already passed there. The tests exposed a missing disposal of the replaced presentation on DOM installation failure, an unhandled setup rejection, collapsed Canvas input errors and both tilemap renderer failures. Substituting main's original `Map`-based queue with only the method renamed reproduced the lost intervening restart. The updated focused suite passed 16 cases across desktop and narrow viewports.

The [final branch CI](https://github.com/oz-coden/Simpludify/actions/runs/42710641447) passed on `bb95d5ea2e8bc8220955b692d7d7a3d56b53a907`. All 18 applicable jobs passed on the first attempt in 6m 53s. The run verified 892 Simpludify unit tests, 462 source browser tests across six shards, Linux and Windows candidate package and starter checks, production smoke builds and both site base paths. The pinned Run To Exit fixture passed typechecking, 35 unit tests, its production build and 66 browser cases across three viewports in WebGL and Canvas2D. The [desktop WebGL job](https://github.com/oz-coden/Simpludify/actions/runs/42710641447/job/129479396221) passed all 11 tests, including the repaired layout case. `deploy` and `published-site` were skipped as expected for the review branch.

## Integration notes

The review branch is ready to integrate into the verified main baseline. That main commit is an ancestor of the tested branch, and the report-only checkpoint records the CI-tested SHA separately from the branch tip.

Pages deployment and the live-site E2E suite run on a successful push to main. The branch verifies production output in CI for both supported base paths. The six live-site scripts also passed against the locally served `/Simpludify/` production build. The public npm check here covers the already released v0.1.6, while candidate checks exercise the renamed SDK API from the branch's tarballs. The distributed starter and Run To Exit's published dependency pins still target their respective released SDKs. Update their shipped dependencies and source together when adopting the next release.

The intermittent desktop Canvas2D camera timeout documented in the [previous CI review](2026-11-09-ci-sdk-candidates.md#main-results) remains tracked separately. Its assertion remains enabled.
